# ربط استوديو جسر الشرق بـ GitHub على Vercel (v27)

## ما تضيفه الحزمة
لوحة التخصيص نفسها على /studio، محمية بتسجيل دخول GitHub لمالك الحساب azizkateb (المعرّف الثابت 243658076). تُحمّل بيانات الموقع والوسائط من أحدث نسخة في azizkateb/jsr-alshark على main، وليست من الإعدادات الافتراضية أو حفظ المتصفح القديم. يظل الموقع العام كما هو، وتظل tools/site-customizer.html لوحة محلية منفصلة.

زر «تحديث المعاينة» لا يحفظ. زر «حفظ ونشر» يعرض تأكيدًا ثم يحفظ المحتوى والوسائط الجديدة في commit واحد، ويبدأ Vercel إعادة البناء عبر ربط Git الموجود. الحفظ ليس دليلًا على نجاح نشر Vercel؛ إذا فشل البناء تبقى النسخة المنشورة السابقة. هذه واجهة ثانية لنفس ملفات GitHub التي يحررها Pages CMS، وليست إضافة داخل خدمة Pages CMS.

## تثبيت الإضافة فوق المشروع الحالي
1. افتح PowerShell داخل مجلد المشروع الذي يحتوي package.json، وتأكد أن تعديلاتك الحالية محفوظة في Git.
2. نفّذ git pull --rebase origin main قبل نسخ الإضافة. إذا ظهر تعارض، توقف وحلّه أولًا؛ لا تستخدم force.
3. فك ZIP وانسخ api وserver وملف tools/site-customizer-cloud.html وvercel.json وdocs/CLOUD-STUDIO-V27.md إلى جذر المشروع، بجانب package.json. لا تنسخ هذه المجلدات داخل public أو src/pages، ولا تستبدل مجلد src/data. إذا كان لديك vercel.json أو ملفات بنفس المسارات مسبقًا، لا تستبدلها دون مراجعة/دمج إعداداتها.
4. من PowerShell داخل المشروع نفّذ:

git add api server tools/site-customizer-cloud.html vercel.json docs/CLOUD-STUDIO-V27.md
git commit -m "Connect protected site studio to GitHub"
git push origin main

5. انتظر نجاح نشر Vercel، ثم افتح https://jsr-alshark-alpha.vercel.app/studio وسجّل الدخول بالحساب azizkateb.

لا توجد ملفات محتوى بديلة في هذه الإضافة؛ لن تعيد تعيين تعديلات Pages CMS أو الأرقام أو التصميم. لا تضف secrets إلى أي ملف في Git. لا يلزم تغيير Astro إلى SSR أو إضافة adapter أو قاعدة بيانات؛ وظائف Vercel موجودة في api بجذر المشروع. تشغيل npm run dev وحده يشغّل الموقع الثابت وليس وظائف Vercel؛ اختبر الربط على عنوان Production المحدد.

## إعدادات أنشأتها مسبقًا
في Vercel، Project Settings → Environment Variables → Production:
GITHUB_APP_ID = 5011854
GITHUB_CLIENT_ID = Iv23liTjxu0bJnyTWa48
GITHUB_CLIENT_SECRET = السر الذي حفظته في Vercel فقط
SESSION_SECRET = الناتج السداسي من randomBytes(32)، بطول 64 حرفًا، محفوظ في Vercel فقط

فعّل Sensitive للسرين. لا نحتاج Private Key أو Installation ID لهذا التدفق؛ التطبيق يعمل نيابة عن المستخدم بعد موافقته، وليس برمز تثبيت مستقل.

في GitHub App: Redirect URI بالضبط https://jsr-alshark-alpha.vercel.app/api/auth/callback، wildcard معطّل، Expire user authorization tokens مفعّل، Webhook غير مفعّل. التطبيق مثبت على jsr-alshark فقط؛ Contents: Read and write وMetadata: Read-only تلقائيًا، دون صلاحيات إدارة/Actions/Workflows.

## الأمان والسلوك
- لا تُرسل أسرار التطبيق أو رمز GitHub إلى JavaScript أو localStorage. رمز المستخدم في cookie مشفرة AES-256-GCM مع Secure وHttpOnly وSameSite=Lax واسم __Host-، ومحددة بمدة رمز GitHub، أقل من 8 ساعات. لا نحفظ refresh_token؛ يعاد تسجيل الدخول عند الانتهاء.
- OAuth state وPKCE، فحص هوية المالك ومعرّف المستخدم الثابت، التحقق من صلاحية push على المستودع لكل طلب بيانات، رمز CSRF وفحص Origin/Host للطلبات المعدلة.
- لا يعمل الربط على روابط Vercel Preview أو دومين آخر حتى يُعدّل العنوان صراحة في server/studio-config.mjs وإعداد تطبيق GitHub.
- لا يمكن للمتصفح اختيار مستودع/فرع/مسار بيانات تعسفي. ملفات المحتوى السبعة فقط في src/data، والوسائط الجديدة تحت public/media/upload-*.
- تحقق خادمي من schema والألوان والتواريخ والروابط وأنواع الوسائط وبداية ملفات الصور/PDF. لا SVG ولا HTML للرفع. لا حذف ملفات ولا استبدال صورة مختلفة بنفس المسار.
- قبل الحفظ، يُقارن أحدث commit بنسخة الأساس؛ إذا تغير المحتوى في Pages CMS أو GitHub، تُرفض العملية وتبقى تعديلات اللوحة. تُنشأ شجرة Git وcommit واحد، ويُحدّث main بدون force. أي سباق لاحق يُرفض أيضًا، ولا يتم تجاوز حماية الفرع. قد تبقى Git objects غير مرتبطة عند رفض آخر خطوة، لكنها لا تُنشر.
- عند تعارض: نزّل نسخة JSON من زر «تنزيل نسخة احتياطية»، ثم «تحميل آخر نسخة»، وأعد تطبيق تعديلاتك المطلوبة فوقها. استيراد نسخة قديمة يستبدل القيم المعروضة، لذلك راجعها قبل الحفظ.
- زر «خروج» يحاول إلغاء رمز المستخدم عبر GitHub ويمسح الجلسة. عند تعذر الإلغاء تعرض اللوحة تنبيهًا، ويمكن إلغاء التفويض من GitHub. تدوير SESSION_SECRET يبطل جميع cookies الحالية.
- يظل بعض السكربت inline لدعم المعاينة الأصلية؛ لا يُسمح بمصادر سكربت خارج الموقع، وتوجد حماية منع تضمين اللوحة في إطارات أخرى. قوالب المحتوى تهرّب النصوص والحقول، والمعاينة داخل iframe sandbox.

## حدود هذه النسخة
- محرر سحابي واحد مصرح: مالك الحساب فقط. دخول العميل بدون GitHub أو دعوات العملاء يحتاج خطوة مستقلة؛ دعوات Pages CMS لا تنتقل تلقائيًا لهذه اللوحة.
- ملف جديد حتى 2 MiB، وطلب الحفظ كله (JSON/base64) حتى 3 MiB، و12 ملفًا جديدًا كحد أعلى للدفعة. احفظ دفعات أصغر عند الحاجة. معاينة ملف موجود حتى 3 MiB؛ يُرفض أكبر منه برسالة واضحة. حدود التصدير المحلي القديمة لا تعني أن الرفع السحابي يقبل الحجم نفسه.
- النسخ الحديثة v24 وما بعدها قابلة للاستيراد في اللوحة المتصلة. النسخة المحلية القديمة تبقى في tools/site-customizer.html إن احتجت ترحيل نسخة أقدم.
- ملفات الوسائط المنشورة عامة، خصوصًا في المستودع العام الحالي. لا ترفع هويات أو جوازات أو بيانات حساسة، أو أسرار، حتى إن أخفيت قسم السير الذاتية.
- إذا ضاع الرد بعد الحفظ بسبب الشبكة، لا تفترض الفشل ولا تستخدم force: افحص commit الأخير في GitHub، واحتفظ بالنسخة المحلية قبل إعادة التحميل.
- الإعدادات الأساسية الأخرى التي لم تتغير في UI تحتفظ بقيمها المحمّلة. إذا أضفت أنواع إعدادات جديدة أو غيّرت مخطط المشروع برمجيًا، يلزم تحديث schema واللوحة معًا.

## التحقق الذي أُجري
اختبارات Node محاكاة لـ GitHub: 13 مجموعة أمان وتكامل (رفض مجهول/غير مالك/CSRF/Origin، صلاحية الجلسة وPKCE، رفض التعارض قبل الكتابة والسباق عند تحديث الفرع، مسارات الوسائط وأنواع الملفات، حجم الطلب، عدم تسريب الرمز، إلغاء الجلسة). اختبارات Chromium للوحة على الكمبيوتر والجوال: تحميل بيانات مختلفة من المستودع، معاينة دون كتابة، تأكيد الحفظ وCSRF ونسخة الأساس، الاحتفاظ بالتعديل عند التعارض، تنزيل النسخة الاحتياطية وعدم تجاوز عرض الشاشة.

هذه الاختبارات تستخدم استجابات GitHub وهمية ولا تنفذ تسجيل دخول أو commits حقيقية. لم تُستخدم أسرارك، ولم يُنشر الربط من هنا. البناء الكامل لـ Astro/Vercel وتسجيل الدخول الفعلي ونجاح الحفظ ثم النشر يحتاج اختبارًا بعد رفعك للحزمة. بيئة الاختبار لا تملك إنترنت؛ أُوقفت الخطوط/الخريطة الخارجية أثناء فحص المتصفح فقط، ولا تزال موجودة في الملفات النهائية.

## عند حدوث مشكلة
- 404 في /studio: تأكد أن vercel.json وapi في الجذر، وأن آخر نشر نجح.
- CONFIG: تأكد من الأسماء الأربعة لمتغيرات البيئة وقيم App ID/Client ID وSESSION_SECRET ذو 64 حرفًا hex، ثم أعد نشر آخر نسخة.
- فشل تسجيل الدخول: تأكد من Redirect URI وتثبيت التطبيق وصلاحية Contents والحساب azizkateb وتفعيل انتهاء الرموز؛ لا تضع أسرارك في سجل أو رسالة دعم.
- PERMISSION: افحص صلاحية التطبيق وحماية الفرع وحدود GitHub، ولا تُعطِ صلاحيات إدارة إضافية لمجرد تجاوز الخطأ.
- CONFLICT: التعديل الأحدث محفوظ؛ صدّر ما عندك ثم حمّل النسخة الأحدث.
